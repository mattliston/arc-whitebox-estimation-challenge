# Matching production OpenBLAS leaves final-layer difference 3.594160079956055e-5 and 15,090 FLOPs bill gap

2026-09-12T20:31Z · experiment · rejected · measured

Of two alternatives (re-run natively with the exact production NumPy 2.4.6/OpenBLAS 0.3.31 libraries, or promote the shared Gram construction to higher precision at an estimated +46.288B F / +11.505% bill), the first was selected as the cheaper diagnostic. The native run with the attested production libraries was byte-repeatable but still differed from the saved production outputs (layers 0/1 exact, layer 2 maximum 7.30e-7, tolerance first crossed at layer 11), so BLAS mismatch was falsified as the sole cause; source review pointed instead to the remote scalar interface discarding the FP32 dtype of indexed gain values.
