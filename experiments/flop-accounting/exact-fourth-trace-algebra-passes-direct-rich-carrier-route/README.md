Both full and organizer-factorized augmented trace sets were checked at synthetic widths8/16 against the organizers' dense power-cumulant conversion and harmonic projection. Complete fourth-trace errors were below3e-16; all intermediate errors were below1e-15. The first version stopped on a helper import before any calculation; v2 repairs it without editing v1. A second, independently organized path sum fuses the FULL augmented pK211 - 2*m*pK111 cancellation. It uses three n-cubed and three n-squared-r products, plus one covariance-centering product and existing repeated planes. It agrees with the dense partial trace below2e-15 and the projected matrix core below6e-16. Repeated-index exclusions and restoration are included. This is real algebraic progress, NOT an accuracy gain. The cost screen uses current rank35/100 active/birth tapes and already metered matrix-kernel polynomials. Optimistically restricting new work to existing active support, core acquisition plus affine/metric pushes alone costs about2.28 times the existing total card. Including only ONE of the three exact fourth-to-third source branches lifts the projection to 3.33/3.34 times the bank's compute, utilization~0.744. Other required work, including the remaining two source branches and third-star contractions, is excluded, so this is optimistic for that representation, not a measured bill or a universal complexity lower bound. At that optimistic cost, raw would need to fall to5.38e-9 merely to cross adjusted4e-9, or1.345e-9 to reach the user's1e-9 goal. There is no accuracy evidence supporting such a gain from this new core. Do not run the direct full-size rich-carrier/fitting route on the strength of the small certificate. This closes that proposed implementation, not all future uses of the trace identity or a genuinely different cheaper representation.
