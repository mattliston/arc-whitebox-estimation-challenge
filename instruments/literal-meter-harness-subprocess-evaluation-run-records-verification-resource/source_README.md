# Phase 2 target-blind synthetic meter protocol

This directory is the single metering path for the Phase 2 Hermite ladder,
CP3, and later estimator variants.  It uses the isolated Phase 2 environment
and the official `whest run --runner subprocess` / flopscope 0.12 path.  There
is intentionally no dataset option: the only weights, inputs, and truth are
deterministic synthetic values generated by whestbench from the recorded seed.

Each run directory retains five files:

- `invocation.json`: exact argv, working directory, limits, and environment
  overrides;
- `raw_whest_stdout.json`: unmodified official JSON report;
- `raw_whest_stderr.txt`: unmodified stderr, including platform warnings;
- `raw_process_tree_rss.jsonl`: 10 ms live RSS samples for the whest evaluator
  and every observed descendant;
- `receipt.json`: postprocessed resource metrics, fixture fingerprints,
  package/source hashes, and target-access assertions.

The fixture receipt hashes every generated weight matrix, the complete sampled
input stream, and both all-layer and final-layer synthetic truth.  It also
reconstructs the weights independently with NumPy and requires exact equality
with whestbench.  These hashes make the run reproducible without checking in a
64+ MiB synthetic network.  Synthetic MSE is deliberately marked unscored: a
1,000-sample local truth is much noisier than the official 1e9-sample targets.
The receipt classifies every exact FLOP count with integer arithmetic against
the 0.1 score-floor condition `10 * flops_used <= 2^41`; the largest integer
count still on the floor is 219,902,325,555 FLOPs.
The compact receipt also records the scored output contract.  A zero-failure
run has passed whestbench's official `(16, 1024)` shape check, float32
materialization, and full finiteness scan; the hashed scoring source binds that
interpretation.

Memory evidence is measured rather than inferred from the configured limit.
On macOS the driver uses `libproc` directly (the sandbox denies `ps`) and
retains every process-tree sample.  The 8 GiB solution comparison uses peak
aggregate descendant RSS, excluding the evaluator root.  The receipt also
retains the OS child `ru_maxrss` as a separate high-water cross-check and states
the important limitation: sampled RSS is neither virtual-address-space usage
nor a guarantee that a spike shorter than the sample interval was observed.

From the workspace root, a Hermite Order10 meter is:

```bash
P2=pure_closure_writeup/problem_graph/experiments/p2_width1024_depth16
"$P2/data_gate/.venv/bin/python" "$P2/meter_protocol/run_synthetic_meter.py" \
  --estimator "$P2/analytic_hermite10_full_covariance/estimator.py" \
  --class EstimatorOrder10 \
  --label hermite_order10_n1_s1000_seed20260823 \
  --n-mlps 1 --n-samples 1000 --seed 20260823 --max-threads 4
```

The same driver meters CP3 by changing only `--estimator`, `--class`, and
`--label`.  An existing label is never changed unless `--overwrite` is explicit.

Verify a retained run without executing the estimator:

```bash
"$P2/data_gate/.venv/bin/python" "$P2/meter_protocol/verify_meter_run.py" \
  "$P2/meter_protocol/runs/hermite_order10_n1_s1000_seed20260823"
```

Timing receipts should be generated only while other CPU/BLAS-heavy jobs are
idle.  FLOP counts are deterministic, but wall and residual time are host-load
sensitive.
